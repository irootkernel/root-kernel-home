AI를 제어하는 핵심 기술은 뭐야?

ROOT KERNEL

핵심은 FSM과 같은 소프트웨어 공학에 기반한 AI 제어 기술입니다. 대표적인 것이 AI-SPARK와 Podway입니다. AI-SPARK는 서버 개발에 필요한 명세를 먼저 검증하고, 사람이 승인한 명세에 따라 AI가 코드를 작성하도록 합니다.

그 원칙은 코드 만드는 일에만 쓸 수 있어?

ROOT KERNEL

아니요. AI-SPARK의 원칙을 분석, 문서 작성, 검토처럼 단계가 있는 다른 작업에도 적용할 수 있도록 넓힌 것이 Podway입니다. 작업 절차와 진행 조건을 미리 정해 두면, 대화나 담당 에이전트가 바뀌어도 현재 단계와 다음에 할 일을 확인할 수 있습니다.

이런 도구들을 내 개발 환경에서도 사용할 수 있어?

ROOT KERNEL

네. Podway는 오픈소스로 공개되어 있으며, Codex 플러그인인 Aquarium을 통해 사용할 수 있습니다. Aquarium은 개발 환경을 확인하고 Podway를 비롯한 도구를 준비해 하나의 작업 흐름으로 연결합니다. 여러 AI의 역할을 나누는 Dolgorae, 테스트 결과를 남기는 Gaori, 코드 리뷰를 돕는 Mulgae, 문서를 다루는 Sanho와 Sorage도 함께 제공합니다. 개발 도구에는 생명이 바다에서 시작되듯, 물개·가오리·산호 같은 수중 동물의 이름을 붙였습니다.

여러 AI가 함께 일하면 역할은 어떻게 나눠?

ROOT KERNEL

Dolgorae가 같은 프로젝트에서 일하는 Codex 에이전트마다 역할과 권한을 정하고, 실행과 협업을 관리합니다. Podway가 작업의 단계와 진행 조건을 맡는다면, Dolgorae는 각 단계를 누가 어떤 권한으로 수행할지 맡습니다.

TECHNOLOGY / Dolgorae

작업 절차와
에이전트의 역할을 연결합니다.

Podway는 진행할 단계와 조건을, Dolgorae는 작업을 맡을 에이전트의 실행과 협업을 관리합니다.

설계 담당구조와 변경 범위구현 담당기능 개발검토 담당코드와 결과 확인

Dolgorae는 Codex 에이전트에 역할과 권한, 행동 규칙과 페르소나를 부여하는 제어 계층입니다. 여러 에이전트가 같은 작업 공간에서 맡은 일을 수행하고 필요한 내용을 주고받도록 실행을 조정합니다.

AI가 일을 제대로 끝냈는지는 어떻게 확인해?

ROOT KERNEL

Aquarium은 보고만 믿지 않고 실제 결과를 확인하는 도구도 연결합니다. Gaori는 테스트 명령의 실제 성공·실패와 원본 로그를 남깁니다. Mulgae는 검토할 코드를 같은 시점의 스냅샷으로 고정하고, 여러 AI가 독립적으로 낸 리뷰를 그 코드와 대조합니다.

TECHNOLOGY / Gaori · Mulgae

테스트 결과와
리뷰의 근거를 확인합니다.

AI의 완료 보고를 실제 실행 결과와 대조합니다.

Gaori

원본 출력은 그대로 보존합니다. 테스트의 성공과 실패는 실행한 명령의 실제 종료 코드를 기준으로 전달합니다.

Gaori GitHub ↗

Mulgae

검토할 코드를 스냅샷으로 고정합니다. 각 AI의 독립적인 보고서를 모으고, 지적의 근거를 검토 대상 코드와 대조합니다.

Mulgae GitHub ↗
YOU

프로젝트가 나뉘어 있으면 문서는 어떻게 관리해?

ROOT KERNEL

Sanho는 각 코드 저장소에 흩어진 문서를 하나의 기준 문서 저장소와 맞춥니다. Sorage는 서로 다른 프로젝트의 AI 세션 사이에서 문서와 검토 의견을 전달하고, 수정본을 주고받게 합니다. 검토 상태와 최종 수락한 문서 버전도 기록합니다.

TECHNOLOGY / Sanho · Sorage

프로젝트 문서를 동기화하고,
검토 의견을 주고받습니다.

저장소가 나뉘어 있어도 각자의 코드 옆에서 문서를 수정하고, 변경 사항을 모아 관리합니다.

Sanho

여러 코드 저장소의 문서를 하나의 기준 문서 저장소와 동기화합니다. Git의 병합 방식으로 변경 내용을 맞추고, 충돌도 평소 사용하는 Git 작업 방식으로 해결합니다.

Sanho GitHub ↗

Sorage

프로젝트의 AI 세션 사이에 문서와 검토 의견을 전달합니다. 수정본을 다시 주고받으며, 검토 진행 상황과 최종 수락한 문서 버전을 기록합니다.

Sorage GitHub ↗

그럼 개발 말고 다른 업무에도 AI를 활용하고 있어?

ROOT KERNEL

네. 루트커널은 여러 업무에서 Hermes Agent를 활용하고 있습니다. Hermes 에이전트를 더 잘 활용하기 위해, 여러 에이전트가 서로 의견을 나누고 토론할 수 있는 ATN(Agent Turn Network)을 만들었습니다. ATN은 진행자와 참여 에이전트의 논의 과정과 결론도 기록합니다.

그렇게 업무에 활용하려면, AI가 참고하는 자료도 계속 최신으로 유지해야겠네?

ROOT KERNEL

맞습니다. 루트커널은 Hermes Agent가 참고할 지식을 정리하는 LLM Wiki를 활용하고 있습니다. 이 위키의 갱신을 돕기 위해 Agent Dispatch를 만들었습니다. 문서 변경을 감지하고 관련 작업을 모아, 설정한 규칙에 따라 Hermes 에이전트에 갱신 작업을 전달하며 처리 결과도 확인합니다.

TECHNOLOGY / Agent Dispatch

문서가 바뀌면
AI에 위키 갱신 작업을 전달합니다.

변경된 Markdown 문서를 모아 위키를 관리하는 에이전트에 전달하고, 처리 결과를 확인합니다.

문서 변경→작업 모으기→Hermes 전달→결과 확인

Agent Dispatch

Markdown 문서의 변경을 감지해, 설정한 규칙에 따라 Hermes 에이전트에 LLM Wiki 갱신 작업을 전달합니다. 반복되는 변경은 모아서 처리합니다.
