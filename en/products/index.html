Sudal, Doksuri, and Ember Quest test Root Kernel's control principles in real operating environments. Sudal tests state transitions in live sessions, Doksuri tests the permission boundary between people and AI, and Ember Quest tests deterministic execution.

Sudal — answer and compare in real time

Sudal helps people who already know one another answer the same questions, compare results, and discover each other's tastes and ideas. It turns similarities and differences that photographs cannot capture into prompts for conversation.

Each gathering opens as a session called a Raft. Participants choose their answers and reach Ready; comparison opens only after everyone is ready.

The AI-SPARK session runtime combines gRPC contracts with an FSM to run this flow. Clients send events rather than changing state directly; the session runtime checks permissions and transition conditions before performing the actual state transition.

Sudal tests whether this control model holds with real users and unreliable networks. Principles proven in the AI-SPARK session runtime carried into the AI-SPARK development process, which spans design through deployment.

Doksuri — Markdown-first project management

Conventional project management tools trap work inside screens and databases, separate from planning documents. Every handoff to AI requires copying context, and the reasoning behind decisions readily drifts away from current state.

Doksuri stores epics, tasks, and bugs as Markdown files. The desktop app, editors, and terminal read the same files, keeping documents and work state together.

AI participates under an identity and permissions separate from a person's account. It may perform low-risk operations such as reading and commenting directly, while changes to content or state are submitted as proposals for human approval.

When a file changes, Doksuri first checks its structure and allowed state. An unvalidated change leaves diagnostics and stops before synchronization; interrupted work is never recorded as success.

Ember Quest — a physics puzzle driven by one ember

Ember Quest is a portrait puzzle RPG about reading an ember's reflected path to relight braziers. Once the player sets direction and force and fires, the shot cannot be taken back, so hidden space and limited time must be judged together.

Presentation is separated from game rules, and the core simulation runs on a fixed tick. The same stage and commands produce the same result across devices and run times, while a replay is an executable record whose state and hash can be compared.

Mazes are authored as data and executed by a shared runtime. Before entering the game, each maze passes structural checks and simulation that reject unreachable braziers and inescapable reflection layouts.
