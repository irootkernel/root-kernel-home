AI Harness

Developing software with AI means picking up ongoing work in a new conversation, comparing code reviews from multiple AI models, and finding failures in long test logs. Documents spread across repositories also need to stay consistent.

Root Kernel built the AI Harness toolset to help with this work. It preserves task state so the next steps remain clear and checks review findings against the actual code. Test logs are summarized with supporting evidence retained, and documents are synchronized with a reference repository. We use these tools in our own development and have released them as open source.

Aquarium

Aquarium is a plugin that helps AI agents set up development tools and use them together. It checks the development environment, helps install tools and configure projects, and connects tools for procedures, testing, code review, and document synchronization during development. Built on Codex, it also offers editions for Claude Code, Kimi Code, and GLM.

Repositoryhttps://github.com/irootkernel/aquarium
EditionsClaude Code·Kimi Code·GLM

Podway

Podway is a local tool that records procedures and progress so people and AI agents can continue their work. When a new conversation begins or another agent takes over, the current stage, required records, and available next actions remain visible. If rework is needed, a path defined in the procedure leads back to the work and validation that must be repeated.

Repositoryhttps://github.com/irootkernel/podway

Dolgorae (dolphin)

Dolgorae is a control plane that gives Codex roles, permissions, behavioral rules, and personas. It runs multiple Codex agents with different roles in a single directory and connects them so they can communicate and collaborate.

Repositoryhttps://github.com/irootkernel/dolgorae

Sanho (coral)

Sanho synchronizes documents across multiple code repositories in one project with a single reference documentation repository. Even when server and client code live in separate repositories, documents can be edited alongside each codebase while their changes are managed together. It detects differences between repositories and reconciles changes using Git merges, with conflicts resolved through the usual Git workflow.

Repositoryhttps://github.com/irootkernel/sanho

Mulgae (seal)

Mulgae assigns code review roles to multiple AI models. It fixes the code under review as a snapshot so all reviewers see the same content. It collects their independent reports and checks the evidence for each finding against the reviewed code. The reports help people decide what to change and in what order.

Repositoryhttps://github.com/irootkernel/mulgae

Gaori (ray)

Gaori runs test commands and extracts the information needed to investigate failures in long logs. People and AI can start with the summary and relevant log excerpts, then consult the originals when needed. Original output is preserved unchanged, and success or failure is reported from the command’s actual exit code.

Repositoryhttps://github.com/irootkernel/gaori

Sorage (hermit crab)

Sorage exchanges documents and review feedback between AI coding sessions working on different projects. The recipient can leave feedback, and the sender can respond with a revised document. It records review progress and the final accepted document version, making it clear what was shared and what was agreed.

Repositoryhttps://github.com/irootkernel/sorage
