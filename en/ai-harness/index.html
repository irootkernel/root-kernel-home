AI Harness

AI Harness is a family of open tools that keeps task state, evidence of completion, and approval authority under human control while agents perform development work.

Root Kernel implements its operating discipline in working tools and publishes them rather than leaving it in documents. These repositories are how the team actually develops with agents, and Root Kernel is their first user.

The tools track task state, compare completion claims with evidence, and leave approval of consequential changes to people. Command success is determined by the actual exit code, while review findings remain advisory until reconciled.

Each README states what the tool enforces and what it does not judge. The shared boundary expands what agents may execute while leaving final approval authority with people.

Aquarium

Aquarium is a Codex plugin that combines several tools into one contract-driven workflow. It does not begin execution before the plan is approved, and it records which tool each stage invokes and which evidence it must receive. Closure follows the declared contract and its human-approval boundary.

Repositoryhttps://github.com/irootkernel/aquarium
EditionsClaude Code·Kimi Code·ZCode

Podway

Podway is a local guard that manages the goal, progress, and next steps of one task in one Git worktree as a procedure graph. A Procedure v2 is selected or configured and checked before the session, then stored as a digest-pinned immutable snapshot. During execution, only declared paths are available; a person or agent reads `allowed_actions` from `podway observe` and chooses the next action. Podway neither performs the work nor verifies the semantic truth of the record.

Repositoryhttps://github.com/irootkernel/podway

Dolgorae (dolphin)

Dolgorae is a local control layer that gives long-running agents stable identity, coordinated write ownership, and recovery. It identifies and resumes the same work after interruption and leaves an auditable record. Conversation text itself is not treated as lifecycle state.

Repositoryhttps://github.com/irootkernel/dolgorae

Sanho (coral)

Sanho synchronizes documentation from multiple application repositories with one canonical documentation repository. It follows Git's merge and conflict rules; the user decides how to resolve conflicts and whether to publish with `git push`. When changed documents synchronize without conflicts, `sanho sync` may create a `[SANHO] Sync docs to <oid>` commit.

Repositoryhttps://github.com/irootkernel/sanho

Mulgae (seal)

Mulgae sends an immutable snapshot to multiple providers for independent review. It reconciles findings against that snapshot and stops fail-closed when a provider lacks a required capability. Reviews provide evidence; they do not own the final decision or permission to change code.

Repositoryhttps://github.com/irootkernel/mulgae

Gaori (ray)

Gaori compresses long test output while preserving the basis for the result. Success and failure come only from the executed command's exit code, and the raw log is retained unchanged. Gaori's summary does not replace the test runner's verdict.

Repositoryhttps://github.com/irootkernel/gaori

Sorage (hermit crab)

Sorage is a local broker for passing documents between AI coding sessions. The receiving side must identify the exact revision it accepts before the exchange closes, and a document in a terminal state remains immutable. Sorage is not an editor, version-control system, or workflow orchestrator.

Repositoryhttps://github.com/irootkernel/sorage
